Response → Customer journey

Host side, end to end: a registration response comes in, gets reviewed, becomes a CRM contact, receives an admission offer for an event, pays, and lands on the customer record with revenue attached. Elements marked PROPOSED do not exist today — they are drawn in place so the seams are visible.

Existing today Proposed addition Gap / broken seam
MAPThe whole pipeline

Left column is the state the object is in. Right column flags what works, what's missing, and where the host gets bounced out of the flow today.

Form response
Submitted
Registration form — identity + answers captured
Response exists independently of a CRM contact. Purposes: application / registration / intake / waiver / feedback / survey.
Review
In review · Waitlisted · Declined · Approved
Host triage + one review note
GAP — no pipeline stages or outreach log. "Called, no answer" can only be a free-text note. Contact buttons are Call / Email / IG / LinkedIn — no WhatsApp at this level.
Conversion
CRM contact
One conversion step per response
GAP — tracked WhatsApp handoff requires contactId (prepareManualSendTask), so messaging, offers and audience queries all bounce through conversion — one response at a time.
Offer · draft
Pick event + recipients + expiry
Payment terms snapshotted at issuance
GAP — event picker lists existing events only; no inline "new event". Missing payment terms bounce the host to event settings.
Offer · issued
Offered
Immutable, revisioned, expires before event start
Payment snapshot frozen: collectionMode, expected amount, currency, reusable page / instructions / personal link.
Delivery
WhatsApp handoff (wa.me)
Rendered message + payment link → host's own WhatsApp
GAP — nothing is sent automatically, nothing is tracked as delivered, and there is no accept/decline link for the recipient. catchCheckout mode exists but is marked unsupported.
Payment · manual
Evidence → Host attested
Host records reference, then attests with bank-check flag
GAP — no "offered & unpaid" attention item or reminder. Attestation writes only to offer/audit collections — never to the contact's revenue facts.
Admission
Admitted → attendee + seat
commitOrganizerFormAdmission consumes the offered offer
Paid offers require hostAttestedReceived + bankReceiptChecked before a seat is written. Free offers admit directly.
Customer record
Timeline + revenue
Sends, replies, notes, attendance, revenue by source
GAP — revenue sees catchPayment, hostImport, hostEstimate, providerOrder. Manually attested offer money is invisible here. Email exists only as a mailto: link — no managed email channel at all.
01Responses

The responses directory for a form. Multi-select feeds the offer flow. The review statuses are the only "pipeline" the CRM has today — there are no custom stages, no outreach outcomes like "called, no answer".

∑The seam list
A
Response-level messaging — WhatsApp (and tracked email later) without forcing contact conversion first. Small: reuse prepareManualSendTask after an inline convert.
B
In-flow event creation — stub event from the offer picker. Medium: new write path + return to draft.
C
Unpaid-offer lifecycle — attention item + optional recipient accept/decline link. Small for the reminder; real contract work for acceptance.
D
Revenue linkage — attested manual payment writes a hostAttested edge fact. Small-medium; the amount/currency are already on the offer.
E
Email channel — no managed email exists today. Largest lift; gates non-WhatsApp markets.
F
Outreach tracking — "called, no answer" needs an activity/attempt model on the contact. Small once the timeline kinds are extended.
